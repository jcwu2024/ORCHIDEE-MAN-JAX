## 判断及其依据

首选保留八层768宽共享主干，将全部字段的共同坐标解码器统一改为
两层384宽、FFN1536、8头，读出隐藏宽256不变。加入一个共享的逐token
768到384线性投影，连接主干和解码器。这是常见的分宽编码/解码设计，
不是已被ORCHIDEE实验验证的科学结论，也不是函数等价的执行优化。

重要依据不是“参数太多”，而是宽矩阵在数千输出坐标上重复使用：

- 已有布局有161个输出字段、8550个静态可用坐标；逐字段补齐后9046个查询。
  两层FFN的源形状前向估算即85.369G MAC。
- 已完成逐字段K/V复用后，daily32/micro4仍需6.626秒，编译live估算21.972GiB；
  历史不同架构daily64/micro8为6.536秒。旧架构的精度不作为合格基线，
  但样本吞吐的差距不能隐去。
- 实际GPU profile含65006个事件，矩阵乘约50.5%、融合算子约46.1%的累计设备时间。
  已识别矩阵乘均为FP32；不能继续把主要问题归咎于没有清理的FP64。
- 实际解码器合并dense计算的15344733作业已完成：micro4仅减少5.3%耗时，
  临时内存增加38.5%。纯分组优化不消除宽FFN的数学运算量。

同一宽度减半时，FFN和方形投影的矩阵运算量降到四分之一；解码器仍有两层
Attention与非线性，所有输出平等使用同一容量。384也与已有规范输入tokenizer
宽度一致，便于复用组件。这些是选它优先测试的理由，不能证明384已是最优宽度。

## 精确改动边界

| 部分 | 本候选 |
| --- | --- |
| 规范输入tokenizer、输入缩放 | 沿用已验收实现 |
| 七个有来源限制的过程流 | 仍共享八层768宽主干权重，保持原信息掩码 |
| 主干到解码器 | 一个共享逐token affine 768→384；不混合token或过程流 |
| family/process/axis/PFT表示 | 在合法family pooling之后、逐输出展开之前投影；1129个源形状token |
| 原始碳库与局部状态 | 仍逐坐标读取，直接编码到384维，保留defined和PFT路由 |
| 字段、标签、坐标/轴/slot embedding | 直接初始化为384维；不经库存平均替代局部输入 |
| 所有输出坐标解码 | 两层384宽、8头、FFN1536；统一共享权重，不区分“辅助”与“主要”容量 |
| 读出 | 384→256→1；物理转换和完整输出shape不变 |
| 科学目标与状态转换 | 原单日+T7+T30联合目标、conservative updater、retained tail和native AD |
| 初始化与优化 | fresh seed与fresh AdamW，全网络联合更新，无探索权重继承 |

投影逐token施加，不允许先混合不同来源再补掩码。带bias的投影后必须恢复
原有无效token归零规则，并沿用attention有效性掩码；all-masked行仍按既有语义处理。
PFT不能引入位置ID学习，所有共享投影必须维持置换等变。
GPP仍可读取原先同PFT/global-PFT允许的2386原始碳坐标；不会只保留七个过程向量。
vcmax25和维护呼吸显式物理参数路由不改，alloc_min/residence_time继续由retained过程处理。

Attention沿用FP32、每头Q/K单位L2及sqrt(head_width)固定尺度；384/8=48，
因此该尺度也随头宽改变。这是明确的新架构定义，不冒充对768模型的数值等价。
保留field-local K/V reuse和query chunk64，不采用已显示内存代价的全字段dense packing。

缩窄是明确的表达容量取舍：所有输出仍可用、梯度仍连通，不代表表达能力不变。
逐token线性降维可能丢掉有用特征，尤其影响局部碳库响应；必须靠真实学习和逐量
rollout证据判断。不得因为技术门通过就称其为合适的最终网络。

逻辑激活体积不是同时驻留量，不能据此承诺micro8可装进显存。

## 为什么不同时展开其他路线

全模型缩窄会同时削弱仅处理少量过程查询的主干，并非此次主要成本靶点。
只砍一层解码器也会改变容量，却只减少约一半解码层运算，且失去第二次条件读取。
按“辅助输出”分配轻量头缺少长期敏感性证据，继续排除。
合并同坐标多个输出通道可能更省，但需要重新证明局部状态、来源及跨字段耦合
语义；当前还没有比统一分宽更明确的收益/实现风险证据，暂不并行建网。
双卡能缩短墙钟，不能消除本次重复计算；在同一新模型单卡成立后再复用已有调度。

## 有限路径：技术通过后直接进入学习

1. **已授权实现一个候选。** 拆分backbone/decoder配置和decoder局部context，
   防止现有`config_width()`及共享`config.width`假定把768偷偷带回解码器。
   保留旧实现用于结构测试与历史读取，不自动迁移旧权重。
2. **本地和部署环境一次完整技术验收。** 覆盖shape/mask/PFT置换、合法与禁止
   输入影响、完整参数和连续状态梯度有限性，以及单日状态/预算。模型函数改变，
   不要求输出或参数梯度等于旧网络；检查新目标自身native AD的JVP/有限差分，
   复用公共rollout，不另写逐日反向。每日/T7/T30检查与两次不同数据的完整AdamW
   更新保留为可续用结果，不为了日志修改重算。
3. **同次验收测真实更新成本。** 从micro4开始；完整daily32、T7、T30以及实际
   组合更新分别计时，记录编译/加载、执行、显存和IO。宽度减少不保证kernel数少。
   工程目标是单卡warm完整更新约12秒以内、峰值不超过既定24GiB。
   12秒对应500次更新纯更新部分100分钟，是可承受预算目标，不是科学定律。
   未达目标先看完整测量，不用小片段的百分比代替，不再盲目追加多个同类优化探针。
4. **满足数值、物理和可接受预算后，开展从头500次联合更新。** 不再只做几十次
   片段测试；复用已核查的500包顺序与数据，32个单日+1条T7+1条T30/更新，全部参数
   优化，LR1e-5、clip1.0等先保持现有方法。技术检查中的更新不继承为训练前史；
   训练从声明seed20260921的update0开始，采样seed20260922。配置和实际新参数数目
   写入新的可执行合同后才能启动；旧固定100步runner不能仅改命令行就冒充500步。

500包已有15985个唯一单日日期；三类合并34424日期、535地点、7502点年、44年份。
这是有界学习段，不是8591565条eligible TRAIN的一个epoch。沿用既有数据，
不重新生产v6，不读v5或sealed test。

建议科学面板为0/100/250/500，固定500端点，不事后择最好checkpoint当通过。
保留原16个TRAIN-fit和48个开发验证窗口；这些“fit”窗口是预先固定TRAIN探针，

GPP、NPP、维持/生长呼吸、RH、AGB/BGB、冠层/DOC/凋落物的变化误差与signed bias。
不通过大库存分母或呼吸分量抵消掩盖漂移。现有非零RH覆盖缺口保持标注。

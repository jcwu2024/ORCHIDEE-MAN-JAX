## Validation Gates

Before using a later-year long run as evidence, do these source-driven checks:

1. Confirm the field appears in `stomate_io_restart_field_scan_20260706.json`
   or is a documented SAVE-only field.
2. Record Fortran file, subroutine, line span, shape, and active/inactive
   branch reason.
3. Map it to one JAX state field, restart field, or explicit unsupported
   branch guard.
4. Add a micro-case or focused diagnostic for the field's local update and
   writeback.
5. Only then use annual modelout as a verification gate.

## Later-Day Overlay Audit: Restart Fields Not Covered By First Pass

Automated comparison of `StomateRestartEntryState` and
`LATER_DAY_STOMATE_ENTRY_STATE_OVERRIDES` initially found three entry fields
not explicitly overlaid from the previous model-produced day:
`fixed_cryoturbation_depth`, `prod10_total`, and `prod100_total`. Comparison
of `StomateRestartSeasonState` and `STOMATE_DAY_SEASON_STATE_FIELDS` found
`date`, `dt_days_read`, and the JAX-only `provenance` metadata field.

Field classifications:

- `fixed_cryoturbation_depth`: true restart/inout state. Fortran reads
  `fixed_cryoturb_depth` in `stomate_io.f90` lines 1235-1240 and writes it in
  lines 2825-2828. Soil-carbon code consumes it under
  `use_fixed_cryoturbation_depth` in `stomate_soilcarbon.f90` lines 2843-2860
  and 3130-3131, with parallel permafrost logic in
  `stomate_permafrost_soilcarbon.f90` lines 3644-3661 and 3778-3779. JAX now
  carries it through the later-day STOMATE overlay and passes the model-produced
  value to OK_LEAK active-layer/soil-carbon boundary construction instead of
  reusing the initial restart image. Paper-case default values remain zero, but
  this is a required state-continuity fix for fixed-cryoturbation micro-cases.
- `prod10_total` and `prod100_total`: derived output diagnostics, not
  independent dynamic restart state. Fortran reads product pools `prod10` and
  `prod100` in `stomate_io.f90` lines 1104-1115, then derives the totals in
  `stomate_lpj.f90` lines 1547-1548 before using them in output diagnostics
  around lines 1578-1663 and 2322. Current JAX restart readers compute totals
  from restart pools and OK_LEAK output inputs can override them; active
  paper-case product pools are inactive/zero. Source-driven product-pool branch
  coverage remains separate from annual-memory state continuity.
- `date`: restart metadata read in `stomate_io.f90` lines 501-506 and used to
  derive the restart day/year context. JAX driver runtime derives current
  year/day/tstep from the forcing loop and does not carry `date` as mutable
  STOMATE process state.
- `dt_days_read`: restart metadata read in `stomate_io.f90` line 501 and
  compared against runtime `dt_days` in `stomate.f90` lines 1824-1827. JAX
  driver runtime uses the active run definition for `dt_days`; restart metadata
  is audited by restart-reader tests but is not part of later-day dynamic state
  overlay.
- `provenance`: JAX audit metadata attached to restart-reader objects, not a
  Fortran process or restart field. It is intentionally excluded from dynamic
  STOMATE state overlay.

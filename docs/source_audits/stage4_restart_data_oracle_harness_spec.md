# Stage 4 Restart/Data Oracle Harness Specification

## Scope

This is a local, source-driven specification for a future Fortran oracle
harness around `stomate_data::data`, `stomate_io::readstart`, and
`stomate_io::writerestart`. It does not run a server, change model code, or
claim that a JAX restart owner is closed.

The machine-readable source of the argument partition is generated by:

```powershell
conda run -n ORCJAX python scripts/dev/generate_stage4_restart_data_oracle_spec.py
```

Its generated artifact is
`docs/source_audits/stage4_restart_data_oracle_interface.json`. The generator
reads declarations directly from the Fortran sources and fails if a formal
argument has no declaration. Groups are mechanically defined by exact Fortran
`INTENT`, declared type, and `DIMENSION`, with all formal arguments retained in
source order. This avoids inventing a semantic grouping or a process formula.

## Source Boundary

| Procedure | Source span | Harness role |
| --- | --- | --- |
| `data(npts, lalo)` | `stomate_data.f90` lines 129-725 | Required initializer ABI; pass fixed one-point coordinates before either restart fixture. |
| `readstart(...)` | `stomate_io.f90` lines 34-1747 | Cold/restart ingress observation target. |
| `writerestart(...)` | `stomate_io.f90` lines 1751-2944 | Restart egress observation target. |

`readstart` and `writerestart` must receive their complete original argument
lists. The generated JSON records their exact ordinal, type, intent,
dimensions, and declaration line, including source facts such as the
`writerestart` `t2m_max_daily`/`wspeed_daily` `INTENT(OUT)` declarations.
Each fixture case also includes a `fixture_fields` entry for every `data`,
`readstart`, and `writerestart` formal, retaining its exact declaration shape
and the permitted harness action. It intentionally does not guess that a
Fortran argument name is its IOIPSL/NetCDF field name.

## Deterministic Fixtures

Both fixtures fix `npts=1`, `index=(/1/)`, `lalo(1,:)=(/45.0,2.0/)`, and
`resolution(1,:)=(/1.0,1.0/)`. Structural constants (`nvm`, `nslm`, `ndeep`,
and the remaining declared dimensions) remain the compiled source constants;
the harness must not replace them with invented values.

| Case | Restart file content | Required capture |
| --- | --- | --- |
| `cold_missing_restart_fields` | Minimal physical template; every STOMATE variable requested through `restget_p` is absent. | Every `readstart` output after the call; every `writerestart` `restput_p` field name and payload after the call. |
| `restart_distinct_typed_payloads` | A template contains each source `restget_p` variable with a non-sentinel typed literal, unique and recorded by variable and axis coordinate. | The same ingress/egress capture, preserving labels and logical-to-real encodings selected by source. |

The payload literals are fixture data, not formulae. The cold case observes
Fortran defaults; the restart case observes Fortran restoration. Neither case
permits a Python/JAX reconstruction of a missing process, a guessed NetCDF
storage order, or a substituted field name.

## Comparison Boundaries

Existing JAX structures are comparison adapters only:
`StomateRestartEntryState`, `StomateRestartSeasonState`,
`StomateDailyAccumulatorState`, `StomateOkPcRestartGasState`, and
`StomateReadstartRemainderState` in `jax_orchidee/stomate/reference.py`; the
template reader/writer is in `jax_orchidee/stomate/restart_io.py`; the finalize
request is in `jax_orchidee/stomate/finalize.py`.

This specification does not assert their ownership or numerical closure.
